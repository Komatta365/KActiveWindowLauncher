# ADR 0002: フロントエンド UI スタックを標準化する

- Status: Accepted
- Date: 2026-08-31

## Context
- 本プロジェクトは Tauri v2 デスクトップアプリとして、頻繁な UI 改修と保守を想定している。
- 実装速度、型安全、デザイン一貫性、再利用性を同時に満たす UI 基盤が必要である。
- 移植対象には、スロット編集・ツールチップ・ドラッグ操作などインタラクティブな画面要件がある。

## Decision
フロントエンド UI スタックとして以下を採用する。

1. **Next.js**
   - フロントエンド基盤・ビルド基盤として利用する。
2. **React**
   - コンポーネント指向で UI 状態を管理する。
3. **shadcn/ui**
   - UI 部品の再利用と一貫したアクセシビリティを担保する。
4. **Tailwind CSS**
   - ユーティリティクラスで高速にスタイリングし、デザインのブレを抑える。
5. **Material Symbols**
   - システムボタンや状態表示のアイコンを統一する。

## Consequences

### Positive
- UI 実装のスピードと変更容易性が高い。
- コンポーネントとスタイルの共通化で保守しやすい。
- 型付き（TypeScript）で UI 層の不整合を早期検知しやすい。

### Negative / Trade-off
- 依存パッケージが増えるため、初期セットアップと更新管理コストが発生する。
- Tailwind と shadcn/ui の運用ルールを揃えないとコードスタイルが分散しやすい。

## Notes
- UI 変更時は本 ADR の採用技術を優先し、別 UI フレームワークの混在は避ける。
